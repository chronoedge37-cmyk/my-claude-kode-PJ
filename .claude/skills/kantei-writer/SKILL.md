# 鑑定文の書き方(kantei-writer)

五行庵宗玄の本鑑定は、AIが書いた鑑定文を練習師(鑑定師)が`260805.html?mode=reading`の
「✨ 一括貼り付け」欄に貼り付けて使う設計になっている(このアプリ自体はバックエンドを持たず、
実際の鑑定文の生成はいつもこのようなチャットセッションで行われる)。このスキルは、その鑑定文を
「当てずっぽうではなく、サイトと完全に一致する命式計算に基づいて」「毎回同じ手順で」
「そのまま貼り付けられる正しい書式で」書き上げるための手順をまとめたものである。

## 0. 前提として毎回確認すること

- 出力は必ず**この会話の返信の中に、コピー&ペースト用のコードブロックとして**書く。
- 見出しは**必ず`【…】`(黒塗り隅付き括弧)を使う**。`〖〗`/`〔〕`も一応読み取れる仕様だが、
  新規に書く時は常に`【】`を使うこと。
- 断定的に書く。「〜かもしれません」「必要であれば」といった逃げ言葉は使わない
  (推奨日・動いてはいけない日は特に厳禁)。
- ⑥総合アドバイスは、必ずこの人固有の日主・命式・希望内容・希望期間に結びつけて書く。
  他の誰にでも当てはまるような一般論は書かない。

## 1. 入力を確認する

以下のどちらかの形で情報が渡される。

- **鑑定師用URL** (`https://.../260805.html?mode=reading&d=<base64>`): `d=`パラメータを
  URLデコード→base64デコードするとJSONが得られる。
  ```python
  import urllib.parse, base64, json
  d = urllib.parse.unquote(raw_d_param)
  data = json.loads(base64.b64decode(d + '=='*(-len(d) % 4)))
  ```
  `data`には `name, email(あれば), Y, M, D, H, Min, gender, action, period, detail, addons, addonOther` が入っている。
- **平文の情報**: お名前・生年月日(・出生時刻)・性別・始めたいこと・希望期間・追加鑑定の希望、
  がそのままチャットに書かれている。URLが無くても全く同じ手順で書ける
  (URLは「一度に間違いなく情報を渡す手段」であって、必須ではない)。

## 2. 命式を、サイト本体と同じ計算エンジンで算出する(絶対に手計算・目算しない)

四柱推命の計算(特に節入りの判定)は単純な日付計算ではないため、必ず`260805.html`自身の
JavaScriptをそのまま実行して命式を出す。手計算やLLMの記憶だけに頼った概算は、実際にサイトが
表示する命式とズレる可能性があるため禁止。

1. `260805.html`から計算エンジン部分だけを切り出す(`// ===== 四柱推命計算 =====`から
   `// ===== ルーティング =====`の直前まで)。
   ```bash
   awk '/===== 四柱推命計算 =====/,/===== ルーティング =====/' 260805.html \
     | sed '$d' > /tmp/bazi_engine.js
   ```
   (`sed '$d'`で末尾の`===== ルーティング =====`の行だけ落とす。行番号を`grep -n`で
   確認してから`sed -n '開始,終了p'`で切り出しても良い。)
2. Node.jsの`vm`モジュールで、DOM関連のスタブを与えて実行する(このファイルにはUI用の
   関数も含まれるが、呼び出さなければ問題ない)。
   ```js
   const fs = require('fs');
   const vm = require('vm');
   const code = fs.readFileSync('/tmp/bazi_engine.js', 'utf8');
   const sandbox = {
     document: { getElementById: () => null, querySelector: () => null,
                 createElement: () => ({ style: {} }), addEventListener: () => {} },
     navigator: { userAgent: '' },
     window: {},
     localStorage: { getItem: () => null, setItem: () => {} },
     console,
   };
   sandbox.window = sandbox;
   vm.createContext(sandbox);
   vm.runInContext(code, sandbox);
   ```
3. 命式を計算する。**出生時刻が不明な場合は必ず`noT=true`(第6引数)を渡す**
   (`H`を`null`にしただけでは時柱が生成されてしまう——`bazi()`の第6引数`noT`だけが
   時柱の有無を制御する)。
   ```js
   const bz = vm.runInContext(`bazi(${Y},${M},${D},${H ?? 'null'},${Min ?? 'null'},${H===null?'true':'false'})`, sandbox);
   const c  = vm.runInContext(`tally(bazi(${Y},${M},${D},${H ?? 'null'},${Min ?? 'null'},${H===null?'true':'false'}))`, sandbox); // [木,火,土,金,水]
   const dy = vm.runInContext(`dayun(bazi(${Y},${M},${D},${H ?? 'null'},${Min ?? 'null'},${H===null?'true':'false'}),'${gender}')`, sandbox);
   ```
   `pk(s,b)`(幹支の読み)、`ST[]`(十干名)、`BR[]`(十二支名)、`EL[]`(五行名 = 木火土金水の順)を
   使って年柱・月柱・日柱(・時柱)、日主、五行集計を人間が読める形にする。
4. **現在の大運を特定する。** `dayun()`が返す`pp`配列の各要素は`{s,b,ay,am}`
   (`ay`歳`am`ヶ月から開始)。今日の日付から見た依頼者の満年齢を計算し、どの`pp[i]`が
   現在に該当するかを求め、`pk(pp[i].s, pp[i].b)`でその10年間の干支を出す。
   **この「今の大運」は、命式の弱点を今の10年がどう補っている/悪化させているかという、
   総合アドバイスの核になる情報なので必ず確認する。**

## 3. 命式を解釈する

- 日主の五行と陰陽、身強/身弱(比劫+印 vs 食傷+財+官のバランス)を見る。
- 五行のうち**ゼロの行、極端に多い行**を必ず特定する。これが命式の一番はっきりした
  「くせ」であり、鑑定文の軸になる。
- 依頼内容(起業・転職・恋愛など)に対して、その「くせ」が何を意味するかを具体的に書く。
  一般的な五行の教科書的説明ではなく、「だからこの人の場合は◯◯が課題/強みになる」という
  この人固有の結論まで落とし込む。
- 今の大運がその「くせ」をどう変化させているか(補っているのか、悪化させているのか)を
  総合アドバイスに必ず反映する。

## 4. 推奨日3日・動いてはいけない日1日を、希望期間の中から実際に計算して選ぶ

日付の吉凶は「なんとなく良さそうな日」を書いてはいけない。希望期間(今日から半年以内、など)の
実際のカレンダー日それぞれについて、同じ`bazi(Y,M,D,null,null,true)`を呼んで日柱(その日の
干支)を求め、以下の基準でスクリーニングする。

```js
for (let d = new Date(startDate); d <= endDate; d.setDate(d.getDate()+1)) {
  const bz = vm.runInContext(`bazi(${d.getFullYear()},${d.getMonth()+1},${d.getDate()},null,null,true)`, sandbox);
  // bz.day.s (十干index 0-9), bz.day.b (十二支index 0-11) を見て判定
}
```

- **推奨日**: 命式で最も欠けている五行(多くはゼロの行)を、幹(できれば支も)にもたらす日を探す。
  幹の五行対応表は `SE=[0,0,1,1,2,2,3,3,4,4]`(甲乙→木、丙丁→火、戊己→土、庚辛→金、壬癸→水)、
  支の五行対応表は `BE=[4,2,0,0,2,1,1,2,3,3,2,4]`(子→水、丑→土、寅→木、卯→木、辰→土、巳→火、
  午→火、未→土、申→金、酉→金、戌→土、亥→水)。欠けている五行を2つ同時に補う日
  (例:甲子=木+水、丙申=火+金)が見つかれば理想的。希望期間の**早い時期・中間・終盤**に
  1日ずつ配置し、「決める→動く→仕上げる」という自然な流れになるようにする。
- **動いてはいけない日**: 命式で既に多すぎる五行をさらに強める日、かつできれば
  日柱の十二支と冲(反対側の支)になる日を選ぶ。冲の組み合わせは
  子午・丑未・寅申・卯酉・辰戌・巳亥。
- 選んだ日は**必ず実際にその干支を計算した上で**書く。「なんとなく大安っぽい日」のような
  当てずっぽうは厳禁。

## 5. タロットを書く

3枚引き(現状・課題・結果)として書き、**必ず次の言い回しをそのまま使う**——
サイト側の`detectTarotCards()`がこの文型でカード名を検出し、実際にそのカードの絵を
報告書に描画する仕様になっているため、この形を外すと絵が汎用的なものにフォールバックしてしまう。

```
現状は「<カード名>(正位置/逆位置)」です。課題は「<カード名>(正位置/逆位置)」です。結果は「<カード名>(正位置/逆位置)」です。
```

- `<カード名>`は大アルカナ(愚者・魔術師・女教皇・女帝・皇帝・教皇・恋人・戦車・力・隠者・
  運命の輪・正義・吊るされた男・死神・節制・悪魔・塔・星・月・太陽・審判・世界)か、
  小アルカナ`<スート>の<ランク>`(スート:ワンド/棒・カップ/杯・ソード/剣・ペンタクル/貨幣/コイン、
  ランク:エース/1〜10・ペイジ/ナイト/クイーン/キング)のどちらか。
- 3枚は思いつきではなく、**②の直前で書いた四柱推命の解釈と必ず筋が通るように**選ぶ
  (例:食傷過多の命式なら現状カードは「発想が湧き出ている」系のカードにする、など)。
- この3行の後に、その3枚が命式の解釈とどうつながるかを説明する文章を続ける。

## 6. 出力形式(このままコピー&ペーストできる形にする)

```
【四柱推命】
(①の本文)

【タロット】
(②の本文。上記5の3行を含む)

【推奨日1】<日付(曜日・干支)>
【推奨日1理由】
(理由)

【推奨日2】<日付(曜日・干支)>
【推奨日2理由】
(理由)

【推奨日3】<日付(曜日・干支)>
【推奨日3理由】
(理由)

【動いてはいけない日】<日付(曜日・干支)>
【動いてはいけない日理由】
(理由)

【総合アドバイス】
(命式・大運・希望期間・推奨日3つ・動いてはいけない日を全部つなげた結論)

【追加鑑定:<label>】
(依頼された追加鑑定ごとに、同じ命式・タロットの手法で1ブロック。<label>は
 「勝負運について」のようなテーマ名で良く、お客様が「その他」欄に書いた生の質問文を
 一字一句繰り返す必要はない——サイト側は見出しの順序でも取りこぼさず拾う仕様になっている)
```

- 追加鑑定が無い場合は最後の`【追加鑑定:…】`ブロックを省略する。
- 依頼者への返信本文には、この鑑定文コードブロックの前に1〜2文だけ、算出した命式
  (年柱・月柱・日柱・五行・現在の大運)の要約を添えると、鑑定師が中身を検算しやすい。

## 参考: このスキルが前提にしているサイト側の仕様

詳しくは`CLAUDE.md`の「Content & product spec」内、"The actual interpretive writing" の
段落と、その後の一括貼り付けまわりの段落群を参照。要点だけ挙げると:

- 一括貼り付け欄(`#bulkPasteInput`)に`?mode=reading&d=...`のURLをそのまま貼るのは誤り
  (見出しが無いので何も反映されない)。必ずこのスキルで書いた鑑定文を貼る。
- 見出しは`【】`/`〖〗`/`〔〕`のいずれでも認識されるが、新規作成時は`【】`を使う。
- 追加鑑定の見出しはラベル一致→見出し順のフォールバックの2段構えで拾われるため、
  お客様の生の質問文をそのまま見出しにする必要はない。
